# Domain invariants

Rules the code must keep. Each has a test; change the test and this file together.

| Invariant | Why | Enforced by |
|---|---|---|
| Originals are never written. Results live in a temp file until the user saves them. Save dialogs refuse all session inputs, including aliases and macOS case variants. | Users must be able to trust the tool with their only copy. | `file_registry.rs` → save-target tests for removed inputs, symbolic/hard links and case variants; `results.rs` (store + atomic copy) |
| A compression result is never larger than its input; otherwise the output is the original, byte for byte (`keptOriginal`). | "Compress" must never make a file worse. | `crates/fileforge-core/tests/pdf_compress.rs` → `output_is_never_larger…`, `corrupted_files_never_panic_and_never_grow` |
| Lossless keeps decoded content identical: page content streams and image bytes are unchanged. | ADR-0003: lossless means lossless. | `lossless_shrinks_structure_and_keeps_every_byte_of_content` |
| Font programs change only by emptying CFF subroutines no glyph calls: charstrings, charset, encoding, FDSelect, subroutine counts and every reachable subroutine stay byte-identical, verified on the rewritten font before it is used; anything the scan cannot model stays as it was. | Every glyph must render exactly as before, in every preset (ADR-0018). | `pdf::cff` unit tests (`the_self_check_rejects…`, `cid_fonts_prune…`), `tests/pdf_fonts.rs` |
| Encrypted PDFs are refused, including owner-password-only files that open without a password. | Rewriting would silently drop the protection. | `encrypted_pdfs_are_refused_even_without_a_user_password` |
| Digitally signed PDFs are refused. | Any rewrite invalidates the signature. | `signed_pdfs_are_refused` |
| PDF/A-1 files keep a classic cross-reference table and readable XMP. | PDF/A-1 forbids object and cross-reference streams. | `pdfa1_files_keep_a_classic_cross_reference_table` |
| Images are downsampled only from placements found on pages, to the densest axis, and only when >15% over the target DPI. | Never make a visible image blurrier than requested. | `images.rs` unit tests, `balanced_downsamples…`, `placement_inside_form_xobjects…`, `images_drawn_nowhere…` |
| Flate-to-JPEG conversion requires explicit `compressFlatePhotos`, a validated gray/RGB image passing the source-pixel screen-content veto, and at least 20% savings against both the source stream and equivalent Deflate. Detected screen content keeps Deflate; classification cannot prove image origin (ADR-0016). | Avoid unnecessary loss of lossless photo pixels and JPEG artifacts on detected UI/text; DPI downsampling remains a separate preset behavior. | `tests/pdf_flate_photos.rs`, `pdf::images` gain/limit tests, `pdf::photos` edge tests |
| Metadata, thumbnails and editing data are removed only on request and never change page content. Files declaring PDF/A, PDF/UA, PDF/X, PDF/E or PDF/VT keep their catalog XMP and Info. The structure tree is never removed. | Privacy and size must not cost a standard claim or accessibility (ADR-0012). | `crates/fileforge-core/tests/pdf_metadata.rs` |
| Unsupported image encodings (CMYK, Lab, Indexed, 16-bit, masks, color-key masks, JBIG2) are left byte-identical. | Better no gain than a corrupted color. | `unsupported_color_spaces_are_left_byte_identical` |
| JPEG 2000 becomes JPEG only for 8-bit gray/RGB images whose codestream matches the dictionary (size, channels, no alpha) and that have no `Decode` or `SMaskInData`; all others are left byte-identical. | PDF ignores `Decode` for JPEG 2000 and may take its alpha as the soft mask; converting those would change how the page looks (ADR-0015). | `jpeg2000_images_become_jpeg…`, `unusual_jpeg2000_images_are_left_byte_identical`, `pdf::jpx` unit tests |
| Images are decoded as reference decoders (libjpeg, OpenJPEG) decode them, so compressing a result again never corrupts it. | zune-jpeg 0.5.15 and hayro-jpeg2000 0.4.0 misdecoded real files (ADR-0015). | `compressing_our_own_output_again_keeps_the_pixels`, `decodes_irreversible_images_like_openjpeg` |
| Lossless image results show exactly the original pixels: a JPEG transcode must decode to the same pixels, a PNG to the same 16-bit RGBA samples, a WebP to the same RGBA samples including the colors of fully transparent pixels; any other candidate is dropped and the original kept. | ADR-0003, ADR-0019 and ADR-0020: lossless means lossless, and a transcoder bug must cost savings, never pixels. | `tests/raster_compress.rs` → `lossless_jpeg_keeps_every_pixel_and_shrinks`, `lossless_png_keeps_every_pixel_and_shrinks`; `tests/raster_webp.rs` → `lossless_webp_keeps_every_sample_and_shrinks_in_every_preset`, `colors_under_full_transparency_survive` |
| Lossless WebPs stay lossless in every preset; lossy WebPs keep their pixels unless a WebP quality is set, and a lossy re-encode keeps the transparency exactly. | Screenshots and graphics must not gain artifacts; transparency is not a quality trade-off (ADR-0020). | `tests/raster_webp.rs` → `lossy_webp_keeps_its_pixels_without_a_webp_quality`, `lossy_reencoding_keeps_transparency_exactly`; `crates/fileforge-webp/tests/encode.rs` |
| A compressed image is never larger than its input; files that are already optimal come back byte for byte (`kept`). A JPEG or WebP re-encode is used only when at least 2% smaller than the best lossless result. | Never worse; no generation loss for a negligible gain (ADR-0019, ADR-0020). | `an_optimized_jpeg_is_returned_byte_for_byte`, `an_optimized_png_is_returned_byte_for_byte`, `an_optimized_webp_is_returned_byte_for_byte`, `lossy_presets_keep_low_quality_sources_lossless`, `lossy_presets_keep_low_quality_webps` |
| Image files whose bytes are signed (C2PA, PNG `dSIG`), that carry data after the image (MPF, gain maps, bytes after the RIFF data) or are animated are returned byte for byte. | A rewrite would invalidate the signature or break the extra images. | `content_credentials_are_never_rewritten`, `extra_data_after_the_image_is_never_rewritten`, `animated_signed_and_extended_pngs_are_never_rewritten`, `animated_signed_inconsistent_and_extended_webps_are_never_rewritten` |
| Image metadata is kept unless removal is asked for; removal keeps ICC profiles, JFIF density, the Adobe segment, PNG color chunks and the EXIF orientation. WebP chunks keep their order. | Removal must not shift colors or rotate photos. | `metadata_survives_by_default`, `removing_metadata_keeps_the_profile_density_and_orientation`, `removing_png_metadata_keeps_color_density_and_orientation`, `png_color_profiles_survive`, `webp_metadata_survives_by_default_in_order`, `removing_webp_metadata_keeps_the_profile_and_orientation` |
| Batch saving never overwrites existing files (`name (2).pdf`), even on simultaneous name collisions. | Saving into a folder must be safe without a dialog per file. | `results.rs` → `unique_paths_never_reuse_existing_names`, `concurrent_batch_saves_never_overwrite_each_other` |

## Background removal (ADR-0022)
- Originals are never modified, including removed inputs and aliases protected by the session registry.
- Compression and background removal register the same source under independent ids and have separate results.
- Transparent output never raises source alpha; retained fully opaque RGB is exact and zero-alpha RGB is zero.
- Image orientation is applied before segmentation; clicks address the full oriented original, even with cropping.
- Crop uses visible alpha bounds plus 2% of the longer side. Solid background is composited after the crop.
- PNG and WebP are lossless 8-bit RGBA, decoded again to verify size, alpha, pixels and ICC. Color profiles are
  preserved; other metadata is removed. A cutout may be larger than its source; the UI shows sizes without savings.
- Missing subjects, malformed masks, non-finite points and cancellation never publish a new result.

Validation: `raster::background` tests, `file_registry` scope test and `results` cutout naming test.
